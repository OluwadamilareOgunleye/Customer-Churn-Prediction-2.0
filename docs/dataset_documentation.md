# Phase 2: Dataset Documentation & Data Dictionary

## 1. Dataset Overview

- **Dataset Name:** IBM Telco Customer Churn Dataset
- **Raw File Location:** `data/raw/Telco_customer_churn.xlsx`
- **File Format:** Microsoft Excel OpenXML Spreadsheet (`.xlsx`), Sheet name: `Telco_Churn`
- **Total Observations (Rows):** 7,043 customer accounts
- **Total Features (Columns):** 33 columns
- **Primary Identifier:** `CustomerID` (100% unique, 7,043 distinct values)
- **Target Variable:** `Churn Value` (integer: `0` = retained, `1` = churned) / `Churn Label` (`No` / `Yes`)

---

## 2. Feature Categorization & Scope

To prevent data leakage and ensure sound machine learning practices, the 33 attributes are categorized into functional groups:

### A. Predictor Features (Included in Modeling Scope)
1. **Demographics (4 features):**
   - `Gender`: Male / Female
   - `Senior Citizen`: Yes / No (senior citizen status)
   - `Partner`: Yes / No (whether customer has a spouse/partner)
   - `Dependents`: Yes / No (whether customer lives with children/dependents)
2. **Account & Contract Terms (3 features):**
   - `Tenure Months`: Number of consecutive months the customer has stayed with the company.
   - `Contract`: Customer's current contract commitment type (`Month-to-month`, `One year`, `Two year`).
   - `Paperless Billing`: Yes / No (whether the customer opted for paperless invoicing).
3. **Subscribed Phone Services (2 features):**
   - `Phone Service`: Yes / No (basic voice service).
   - `Multiple Lines`: Yes / No / No phone service.
4. **Subscribed Internet Services & Add-ons (7 features):**
   - `Internet Service`: Customer's internet backbone (`DSL`, `Fiber optic`, `No`).
   - `Online Security`: Yes / No / No internet service (antivirus/security suite).
   - `Online Backup`: Yes / No / No internet service (cloud storage backup).
   - `Device Protection`: Yes / No / No internet service (hardware warranty/protection).
   - `Tech Support`: Yes / No / No internet service (priority technical assistance).
   - `Streaming TV`: Yes / No / No internet service (third-party TV streaming).
   - `Streaming Movies`: Yes / No / No internet service (third-party movie streaming).
5. **Billing & Charges (3 features):**
   - `Payment Method`: `Electronic check`, `Mailed check`, `Bank transfer (automatic)`, `Credit card (automatic)`.
   - `Monthly Charges`: Current monthly billing amount ($).
   - `Total Charges`: Cumulative charges billed across tenure ($).

### B. Target Variables
- `Churn Value`: Binary integer (`1` for churned, `0` for retained). Primary target for binary classification.
- `Churn Label`: String representation (`Yes` / `No`).

### C. Excluded Features (Data Leakage & Non-Predictive)
- `CustomerID`: Unique primary key; high cardinality with no generalization capacity.
- `Count`: Constant value (`1` across all 7,043 rows); zero variance.
- `Country`: Constant value (`'United States'` across all rows); zero variance.
- `State`: Constant value (`'California'` across all rows); zero variance.
- `City`: High-cardinality categorical variable (over 1,100 Californian cities).
- `Zip Code`, `Lat Long`, `Latitude`, `Longitude`: Spatial coordinates reflecting local California distribution; excluded to prevent overfitting on local geographic noise.
- `Churn Reason`: **Severe Target Leakage**. Only populated when `Churn Value == 1` (1,869 rows); missing (`NaN`) for all active customers (5,174 rows). This column is collected during exit interviews post-churn.
- `Churn Score`: **Target/Model Leakage**. A proprietary 0–100 risk score generated by IBM's pre-existing statistical model. Using it as a predictor would leak the existing model output.
- `CLTV`: Calculated Customer Lifetime Value derived using tenure, charges, and historical formula.

## 4. Initial Data Quality & Anomaly Observations

1. **`Total Charges` Whitespace Blanks:**
   - In 11 records out of 7,043 (0.156%), `Total Charges` contains a blank whitespace string (`" "`), causing the column to be ingested as `object` rather than `float64`.
   - In all 11 records, `Tenure Months` equals `0`. These represent newly onboarded subscribers who have not completed their first billing cycle.
   - Domain-sound correction: Replace blank spaces with `0.0` and cast to `float64`.

2. **Target Class Imbalance:**
   - Negative class (`0` / `No`): 5,174 customers (73.46%).
   - Positive class (`1` / `Yes`): 1,869 customers (26.54%).
   - The dataset exhibits moderate class imbalance (~2.77 : 1 ratio). Accuracy will be an uninformative standalone metric; Precision, Recall, PR-AUC, and ROC-AUC are essential.

3. **Duplication Audit:**
   - Exact duplicate rows: 0.
   - Duplicate `CustomerID` instances: 0 (7,043 unique accounts).
