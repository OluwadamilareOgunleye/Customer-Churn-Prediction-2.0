# Phase 4: Data Quality, Cleaning, and Preprocessing Decisions

## 1. Overview & Objectives

Phase 4 transforms the raw IBM Telco Customer Churn dataset into a clean, machine-learning-ready format. All transformations strictly adhere to industry standards:
1. **Zero Data Leakage:** Preprocessing transformations are defined via Scikit-Learn `ColumnTransformer` and fitted exclusively on training splits during modeling.
2. **Raw Data Preservation:** The raw Excel file `data/raw/Telco_customer_churn.xlsx` remains completely untouched. Cleaned train and test sets are saved separately in `data/processed/`.
3. **Reproducibility:** A fixed random state (`42`) and stratified splitting ensure identical, defendable data splits.

## 2. Preprocessing & Cleaning Decision Table

| Issue | Affected Feature(s) | Investigation Findings | Action Taken | Technical & Business Justification |
| :--- | :--- | :--- | :--- | :--- |
| **Whitespace string values causing object dtype** | `Total Charges` | Exactly 11 out of 7,043 rows (0.156%) contained a whitespace character `" "`. In all 11 records, `Tenure Months == 0`. | Replaced `" "` with `0.0` for records with `Tenure Months == 0`, and coerced the column to `float64`. | Customers with zero tenure are new subscribers who joined during the current billing cycle and have not yet been billed. Dropping them would discard valid customer records; replacing with mean/median would distort true zero spend. |
| **Data Leakage from post-churn information** | `Churn Reason` | Feature is populated only for churned customers (1,869 non-null, 5,174 NaN). Recorded during exit interviews. | Excluded entirely from feature set $X$. | Including post-churn exit survey feedback creates catastrophic lookahead leakage ($\text{Churn Reason is not null} \Rightarrow \text{Churn} = 1$). |
| **Target / Pre-existing Model Leakage** | `Churn Score` | Contains a 0–100 risk score generated by IBM's proprietary baseline predictive model. | Excluded entirely from feature set $X$. | Using a pre-existing model's output as an input feature creates circular target leakage. Our goal is to train a model from primary attributes. |
| **Derived Business Metric** | `CLTV` | Calculated customer lifetime value derived from historical churn formula and charges. | Excluded from feature set $X$. | Prevents synthetic metric circularity and multicollinearity with tenure and charges. |
| **Redundant Target Representations** | `Churn Label` | String representation (`"Yes"` / `"No"`) of the binary target. | Retained `Churn Value` ($1/0$) as primary target; excluded `Churn Label` from $X$. | Eliminates duplicate target column. |
| **Zero Variance (Constants)** | `Country`, `State`, `Count` | `Country` is 100% `"United States"`; `State` is 100% `"California"`; `Count` is 100% `1`. | Dropped from feature set $X$. | Zero-variance features carry zero predictive entropy and add unnecessary column dimensions. |
| **High Cardinality Spatial Identifiers** | `CustomerID`, `City`, `Zip Code`, `Lat Long`, `Latitude`, `Longitude` | `CustomerID` has 7,043 unique IDs (no duplicates). `City` and `Zip Code` have hundreds of high-cardinality levels. | Excluded from predictive feature matrix. | Identifiers cannot generalize; high-cardinality California geographic coordinates risk overfitting to localized neighborhood noise. |
| **Categorical Whitespace Consistency** | All categorical columns | Checked for leading/trailing whitespace across nominal features. | Applied `.str.strip()` across all categorical variables. | Prevents silent mismatches in one-hot encoding categories (e.g., `"Yes "` vs `"Yes"`). |
| **Extreme Outlier Assessment** | `Monthly Charges`, `Total Charges`, `Tenure Months` | Distribution analysis revealed maximum tenure is 72 months, maximum monthly charges is $118.75. All values fall within standard telecom plan pricing. | Retained all observations; no artificial capping or deletion. | Values reflect genuine subscriber contracts and commercial plan ceilings, not measurement or entry errors. |

## 3. Data Splitting & Leakage Prevention Strategy

- **Splitting Method:** Stratified Train-Test Split via `sklearn.model_selection.train_test_split`.
- **Stratification Target:** `Churn Value` (maintaining exactly 26.54% churn rate across both splits).
- **Split Ratio:** 80% Train (5,634 rows) / 20% Test (1,409 rows).
- **Random State:** `42`.
- **Validation:** Automated test `test_validate_train_test_split` verified zero index overlap and balanced class proportions ($|\Delta_{\text{churn rate}}| = 0.0000 < 0.05$).

```
Total Clean Observations (7,043)
  ├── Training Set (5,634 rows, 80%) ── 1,495 Churners (26.54%) | 4,139 Retained (73.46%)
  └── Test Set     (1,409 rows, 20%) ──   374 Churners (26.54%) | 1,035 Retained (73.46%)
```

## 4. Reusable Pipeline Architecture

The preprocessing transformation pipeline is constructed using Scikit-Learn's `ColumnTransformer`:

### Numerical Feature Pipeline (3 features)
- **Features:** `Tenure Months`, `Monthly Charges`, `Total Charges`
- **Step 1:** `SimpleImputer(strategy="median")` — Guarantees robustness against unexpected missing numerical values at inference time.
- **Step 2:** `StandardScaler()` — Centers numerical variables to mean $\mu = 0$ and scales to unit variance $\sigma = 1$, essential for distance-based and regularized linear classifiers (Logistic Regression).

### Categorical Feature Pipeline (16 features)
- **Features:** `Gender`, `Senior Citizen`, `Partner`, `Dependents`, `Phone Service`, `Multiple Lines`, `Internet Service`, `Online Security`, `Online Backup`, `Device Protection`, `Tech Support`, `Streaming TV`, `Streaming Movies`, `Contract`, `Paperless Billing`, `Payment Method`.
- **Step 1:** `SimpleImputer(strategy="most_frequent")` — Handles any missing categorical tokens at inference.
- **Step 2:** `OneHotEncoder(handle_unknown="ignore", sparse_output=False)` — Encodes nominal categories into binary indicator columns. The `handle_unknown="ignore"` parameter ensures that unseen category levels encountered in production inference do not crash the pipeline, but gracefully map to all zeros.
